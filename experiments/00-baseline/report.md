# 00-baseline

상태: 초기 수동 관찰 완료. API 측정과 반복 실험은 미완료.

## 질문과 가설

출력 길이가 응답 완료 시간에 어떤 영향을 주는가?

가설: 입력 길이가 비슷할 때 출력 토큰이 늘면 Decode 시간과 응답 완료 시간이 늘어난다.

## 환경과 실행 방법

- 환경: [환경 기록](../../docs/environment.md)
- 런타임: Ollama (버전 미기록)
- 모델: `llama3.1:8b`, 로컬 표시 ID `46e0c10c039e`
- 사용자 제공 `ollama ps` 출력: `100% GPU`, 로딩 크기 9.2 GB, context 32768
- 결과 출처: 사용자가 제공한 CLI 출력. 별도 JSON 원시 파일은 없다.

각 명령을 별도 실행하여 대화 기록 누적을 피했다.

```bash
ollama run llama3.1:8b "서울에 대해 한 문장 으로 설명해줘." --verbose
ollama run llama3.1:8b "서울에 대해 열 문장 으로 설명해줘." --verbose
```

## 실험 조건

- 변경: 답변 길이에 대한 자연어 요청 (한 문장 / 열 문장)
- 공통: 로컬 장비, 모델, 입력 토큰 수 22개
- 조건별 실행 횟수: 1회
- 모델 로딩 시간: 두 실행 모두 약 1.4 ms
- 생성 설정, Cache 상태, 백그라운드 부하: 통제하지 않음
- 요청한 문장 수는 실제 출력 토큰 수를 보장하지 않음

## 해석

입력 토큰 수는 같고 입력 처리 시간도 비슷했다. 출력은 약 18.4배, 출력 생성 시간은 약 19.8배 늘었다. 이번 관찰에서 전체 시간 증가는 대부분 출력 생성 시간 증가로 설명된다.

출력 생성 속도의 차이는 반복 측정 없이 일반화하지 않는다. `100% GPU`는 모델의 GPU 배치를 나타내며 GPU 사용률 측정값이 아니다.

## 한계와 다음 실험

- TTFT와 TPOT는 별도로 측정하지 않았다. 입력 처리 시간은 TTFT가 아니다.
- 런타임 버전과 실제 dtype / 양자화는 미기록이다.
- 모델이 생성한 내용의 정확성을 평가한 실험은 아니다.
- 다음: Ollama API 요청과 JSON 저장 구현 후 스트리밍으로 TTFT를 측정한다.
- 이후: 반복 측정과 입력 길이 변경 실험을 진행한다.
